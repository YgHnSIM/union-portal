Chapter 01 · Fundamentals

제1장. 비개발자 관리자를 위한 기초 개념 안내 (시작하기 전에)

1.1 이 시스템은 왜 이렇게 만들어졌는가?

노동조합을 투명하게 운영하려면 조합원 누구나 스마트폰에서 회계 장부, 회의록, 성명서, 규약을 쉽게 볼 수 있어야 합니다. 하지만 동시에 조합원 명부, 가입서 스캔본, 연락처, 경조사 내역 같은 민감한 개인정보는 단 한 글자도 외부 인터넷에 새어 나가선 안 됩니다.

union-portal은 "사무실 내 컴퓨터 속 비밀 금고(로컬 정본)"와 "누구나 볼 수 있는 전시장(공개 정적 웹사이트)"을 완전히 분리해 놓고, 그 사이에 자동화된 개인정보 지우개 + 이중 보안 검문소를 세워 둔 시스템입니다.

1.2 꼭 알아야 할 IT 기초 개념 10가지 (쉬운 비유 사전)

비개발자 관리자를 위한 10대 핵심 기술 개념과 일상 비유
번호 기술 용어 일상 비유 (쉽게 이해하기) union-portal에서의 실제 역할
01 정적 웹사이트 & GitHub Pages 24시간 경비원이 서 있는 백화점(서버)이 아니라, 미리 인쇄한 책자 묶음을 무료 전시장에 진열하는 방식 서버 유지비(월 비용)가 0원이며, 서버 해킹으로 조합원 DB가 탈취될 위험이 원천적으로 없습니다. _site/ 폴더가 완성된 책자 묶음입니다.
02 로컬(Local) vs 원격(GitHub) 내 사무실 책상 잠금 서랍(내 PC) vs 인터넷 공용 진열장(GitHub) 개인정보 원본은 내 PC에만 보관하고, 개인정보가 지워진 파일과 프로그램 코드만 git push로 GitHub에 보냅니다.
03 .gitignore (출입 통제 명단) 택배 상자에 절대 넣지 말아야 할 물품을 적어 둔 자동 금지 스티커 data/local/, _raw/, directory/, reports/, _site/, .env가 실수로 GitHub에 올라가지 못하게 자동 차단합니다.
04 SQLite 데이터베이스 (union.db) 여러 장의 엑셀 시트가 서로 어긋나지 않게 묶여 있는 "스마트 정본 금고 파일 1개" 조합원·외부인·직책 이력·별칭·원장·문서 연결을 data/local/union.db 1개 파일에 외래키 제약조건과 함께 안전하게 저장합니다.
05 공개 투영 (data/public/) 비밀 문서 원본에서 이름·연락처를 검은 펜으로 가리고 통계 숫자만 옮겨 적은 요약본 export-public 명령이 정본 DB에서 개인정보를 제거해 추출하는 정제 JSON 스냅샷입니다. 이 폴더만 GitHub에 올라갑니다.
06 단방향 해시(HMAC-SHA256) & 솔트 이름을 암호 지문으로 바꾸는 믹서기. 지문만 보고는 원래 이름을 복원할 수 없지만, 글에 이름이 섞였는지는 100% 적발 가능 GitHub에는 이름 대신 지문 목록(privacy_hashes.json)만 올립니다. GitHub Secret의 비밀 솔트(PRIVACY_HMAC_SALT)로 실명 누수를 차단합니다.
07 CLI (명령줄 도구, union) 복잡한 메뉴 대신 터미널에 짧은 명령 한 줄을 입력해 실행하는 "만능 리모컨" 조합원 가입, 원장 동기화, 공개본 추출, 개인정보 감사, 사이트 빌드, A2/A3/A4 PDF 생성을 모두 한 줄로 처리합니다.
08 TypeScript & Node.js 22 LTS 과거 회계(Python)와 자료실(JS)의 서로 달랐던 공용어를 하나로 통일한 설계 언어 인명 정규화·개인정보 검사·SVG 차트 생성·PDF 출력·웹 빌드가 단일 언어로 통합되어 중복과 불일치가 사라졌습니다.
09 Markdown / YAML / JSON 문서 서식(.md), 문서 표지 카드(YAML), 컴퓨터용 데이터 표(JSON) 회의록은 .md로 작성하고, 표지 정보는 상단 --- 사이에 적으며, 규약 심의안과 계정 설정은 .json으로 관리합니다.
10 CI/CD (GitHub Actions 검문소) 공항 보안검색대: 올릴 때마다 로봇이 계산·링크·개인정보를 검사하고 통과해야만 공개 main 브랜치에 푸시할 때마다 자동으로 typecheck, test, build:site, validate:ci를 거쳐야만 GitHub Pages에 배포합니다.

제3장. 3대 도메인 컨텍스트와 표준 용어 사전 (GLOSSARY-MAP)

union-portal은 조직(Organization), 회계(Accounting), 자료실(Archive) 세 가지 도메인으로 나뉘며, 문서와 코드 전체가 동일한 표준 어휘를 사용합니다.

3.1 조직 (Organization) 컨텍스트 (src/organization/GLOSSARY.md)

config/units.json에 등록된 조합 공식 조직·회계단위 4곳
코드 공식 명칭 약칭 전체 명칭 상태 담당 역할 및 비고
HQ 본조 본부 우체국물류지원단 물류노동조합 본조합 운영중 (active) 조합비 수납, 교부금 배분, 중앙 교섭·복지 총괄 (시트: 원장_본부)
AY 안양지부 안물 안양물류센터지부 운영중 (active) 안양물류센터 현장 지부 (시트: 원장_안물)
BP 부평지부 부평물 부평물류센터지부 운영중 (active) 부평물류센터 현장 지부 (시트: 원장_부평물)
SS 서서울지부 서물 서서울물류센터지부 폐지 (closed) 2024년 3월 폐지, 잔여노조비 1,000,000원 본부 회수 완료(과거 자료 보관용)
  • 조직단위 vs 사업장(사업소): 지부는 조합 조직 단위이며, 사측 근무 현장은 사업장(사업소)으로 구분합니다. (Avoid: 분회, 지점, 센터)
  • 인물 통합 모델: 조합원(M-XXXX)과 외부 인사(E-XXXX)를 people 상위 개체로 통합합니다.
  • 공적 노출 등급 & 7대 직책 구분(roleScope): 선출·임명 공식 직무자(executive 집행부, branch_head 지부장, auditor 감사, committee 특별기구) 및 외부 대표(external_rep)의 공적 직무 활동만 임기 내 실명 공개를 허용합니다. 반대로 순번제 소통간사(staff_rotating)와 other는 무조건 비식별(masked) 강제 대상입니다.
  • 개인·재정 정보 전면 비식별 & 인명 표기: 전·현직 임원도 회계 원장, 개인 찬조, 경조사, 실비 문맥에서는 전면 비식별합니다. 내부 원장은 정식 성명만(name_only), 공적 문서는 직책 병기를 허용합니다.

3.2 회계 (Accounting) 컨텍스트 (src/accounting/GLOSSARY.md)

재원 구분 (2종)

일반회계(정기 조합비·통상 경상비)와 특별모금·찬조(소송 연대·워크샵 등 목적성 기금)로 분리 집계합니다.

6대 거래 구분 (gubun)

수입, 지출, 내부이전(전입), 내부이전(전출), 기초이월(2022.12.23 승계), 이월차액. 본부↔지부 내부이전은 통합 결산 시 자동 상계됩니다.

보고월 vs 귀속월

보고월(ym)은 월별 결산 마감 기준 월이고, 귀속월(attrYm)은 실제 입출금일과 무관하게 해당 회비·교부금이 귀속되는 대상 월입니다.

10대 지출형태 (expType)

식대, 다과·음료, 인쇄·제작, 물품·비품, 선물·상품권, 교통·숙박, 경조금·화환, 찬조·기부금, 교부·환급, 기타.

3단계 계정과목 체계 (관 → 항 → 목, config/coa.json): 수입은 3대 관(조합비수입, 기부·찬조수입, 기타수입), 지출은 5대 관(운영비, 교섭·투쟁·권익비, 조직·교육비, 조합원복지·연대비, 조정·환급)에 내부이전·기초이월을 더해 총 10개 관으로 구성됩니다.

3.3 자료실 (Archive) 컨텍스트 (src/archive/GLOSSARY.md)

  • 5대 자료 문서 범주: 성명서(statement), 소식지(newsletter), 운영위원회 회의록(mom — 회의록/종합결산), 지식(knowledge), 알림(notice).
  • 3단계 게시 가시성(visibility): public (전체 공개) 목록·사이트맵·검색 노출 / unlisted (미등재) HTML 생성하되 목록·사이트맵 제외 및 noindex,follow / internal_only (내부 전용) 공개 빌드 원천 제외.
  • 기준월(financePeriod) & 문서-거래 연결: 회의록은 기준월 재정 현황을 자동 연동하며, document_ledger_links로 문서와 거래번호(tx_id)를 양방향 상호 참조합니다.
  • 규약 개정 다회차 심의: 초기 검토 시안(불변 기준선) 대비 회의 반영 잠정안을 5단계 심의 상태(pending → scheduled → discussing → confirmed_revision / confirmed_current)와 상정 차수(wave-1/wave-2/unassigned)로 누적 관리합니다.
Chapter 04 · Architectural Decisions

제4장. 7대 핵심 아키텍처 결정 기록 (ADR-0001 ~ ADR-0007)

docs/adr/에 기록된 7건의 핵심 설계 결정과 실무 영향
ADR 번호 결정 제목 해결하려는 문제 (배경) 기각된 대안 관리자 실무 결과
ADR-0001 비로그인 정적 공개 포털 + 로컬 관리 우선 & 클라우드 경계 약 60명 규모에서 상시 서버·DB 운영은 비용과 해킹 위험이 과도함 초기 클라우드 서버 구축 / 추상화 없는 단순 스크립트 유지비 0원 정적 사이트로 운영하되, Repository·BlobStorage 인터페이스로 클라우드 전환 대비

제7장. 기능 단위별 작동 원리 (8대 핵심 서브시스템 심층 해부)

7.1 조합원 · 외부인 · 직책 · 별칭 관리 (MemberService)

src/services/member-service.ts는 모든 인사 변동을 데이터베이스 트랜잭션 안에서 처리합니다.

  • 가입 & 자동 재가입 판정: joinMember()는 입력된 --unit(코드·정식명·약칭 모두 인식)을 표준 코드로 변환한 뒤, 이름 + 생년월일이 일치하는 기존 비현역 조합원 1명이 발견되면 자동으로 재가입(rejoin)으로 전환해 기존 M-XXXX 번호와 최초 가입일(firstJoinedOn)을 승계합니다.
  • 증빙 보관 & 금칙어 자동 등록: 첨부된 가입서/탈퇴서 스캔본은 LocalFileStorage가 경로 탈출(../) 검사를 거쳐 _raw/applications/JOIN_YYYYMMDD_M-XXXX_이름.ext 키로 저장하며, 가입 시 해당 이름이 privacy_rules(forbidden_name)에 자동 등록됩니다.
  • 탈퇴 시 환급 검증 & 직책 자동 종료: withdrawMember()는 --refund-tx가 주어지면 실제 원장(ledger_entries)에 존재하는 거래번호인지 검증하고, 해당 조합원이 맡고 있던 모든 현임 직책을 endReason: '탈퇴'로 자동 마감합니다.
  • 소통간사 비공개 강제 가드: appointRole() 및 transferRole()은 roleScope === 'staff_rotating'(순번제 소통간사)을 public_official로 공개하려 하면 ADR-0003 위반 에러를 발생시켜 실수를 원천 차단합니다.

7.2 인명 정규화 엔진 (person-normalizer.ts)

원장에 "홍길동 위원장님", "길동 형", "김철수님 모친상"처럼 뒤섞여 입력된 표현은 normalizePersonMentions()의 3단계 파이프라인을 거쳐 정식 성명만으로 깔끔히 정리됩니다.

  1. 1단계 (별칭 해결): person_aliases를 긴 별칭부터 순차 치환합니다. exact 모드는 앞뒤가 한글이 아닐 때 무조건 바꾸고, context_title 모드는 뒤에 직책·호칭이 따라올 때만 바꿉니다.
  2. 2단계 (등록 성명 앞뒤 수식어·직책·존칭 박리): strip_tokens(존칭 님/씨/선생님, 수식어 전/현/직무대행/신임, 직책 위원장/사무국장/지부장/반장...)를 조합한 정규식으로 이름 앞뒤에 반복적으로 붙은 수식을 한 번에 제거합니다.
  3. 3단계 (일반 존칭·경조사 폴백 + 비인명 보호): 미등록 2~4글자 한글 이름 뒤의 띄어쓴 존칭(SPACED_HONORIFIC_RE)과 경조사(모친상/결혼/퇴직 등) 앞 님을 제거하되, NON_PERSON_WORDS(부모님, 어머님, 아버님, 선생님, 하느님 등 10개)는 보호합니다.

7.3 회계 원장 단방향 동기화 및 3대 검증 (sync-ledger.ts, accounting.ts)

  1. 엑셀/JSON 파싱: .xlsx의 '통합원장' 시트 18개 열을 읽으며, Google Sheets 내보내기 시 생기는 IFERROR(__xludf.DUMMYFUNCTION(...)) 수식 래퍼나 RichText를 자동 해제해 실제 값을 꺼냅니다. 이후 normalizePersonMentions()로 인명을 정규화합니다.
  2. 3대 무결성 검증 (validateLedgerRecords): ① 모든 행의 (구분, 관, 항, 목)이 config/coa.json에 등록되어 있는지, ② #REF!·#NAME?·#VALUE!·#N/A 수식 오류가 없는지, ③ 회계단위별 누적 잔액(이전 잔액 + inc - exp === unitBal)이 1원 오차도 없이 일치하는지 검증합니다.
  3. 참조 무결성 게이트 & 인물 매핑: 기존 document_ledger_links나 membership_events.refund_tx_id가 참조하는 tx_id가 새 파일에 누락되면 즉시 동기화를 롤백합니다. 통과 시 ledger_person_links를 최신화하고 sync_metadata에 동기화 기록을 남깁니다.

7.4 차등 프라이버시 마스킹 및 공개 투영 추출 (privacy.ts, export-public.ts)

exportPublicProjection()은 .env(또는 환경변수)의 PRIVACY_HMAC_SALT(없을 경우 32바이트 난수 자동 생성)를 이용해 data/public/에 5개 파일을 생성합니다.

  • ledger_public.json: sanitizeLedgerRecords()가 target을 targetMask 또는 '개인'으로, note를 exactNoteReplacements 또는 '관계자'로, memo 내 인명을 '관계자'로 치환합니다.
  • org_summary.json: 개인정보 없이 단위별 조합원 수, 고용/근무 분포, 월별 입·탈퇴 흐름 숫자만 집계합니다.
  • public_officials.json: public_disclosure === 'public_official' 직책만 추출하되 연락처·생년월일은 제외합니다.
  • document_ledger_links.json: 문서 ID ↔ 거래번호 연결 목록.
  • privacy_hashes.json: 모든 성명·금칙어·exact 별칭·전화번호(숫자형 포함)·이메일을 HMAC-SHA256(token, salt)로 일방향 해싱한 지문 목록과 한글 길이 인덱스(hangulLengths)만 저장합니다.

7.5 자료실 콘텐츠 그래프 v3 및 문서 렌더러 (content-graph.ts, mom-renderer.ts, statement-fragment.ts)

  • content-graph.ts: catalog.json, topics.json, sources.json, mom/*.md Frontmatter를 읽어 Ajv(JSON Schema Draft 2020-12 strict 모드)로 검증하고, route 안전성·날짜 순서·주제/출처/관련문서 상호 참조·socialImage 실존 여부를 검사합니다.
  • mom-renderer.ts: 회의록을 markdown-it(html: false)으로 안전하게 변환하고, <br>만 예외 허용하며, 위험 링크 스킴(javascript: 등)을 차단하고, 표마다 .table-wrapper와 모바일 카드용 data-label을 자동 부착합니다. 또한 ** 짝 불일치나 \[ 잔재를 잡아냅니다.
  • statement-fragment.ts: 성명서 .body.html을 parse5 AST로 파싱해 허용 태그 11종·허용 클래스 8종·마지막 최상위 closing-block 구조를 강제하고, 글자수·문단·줄바꿈·소제목·요구항목·제목줄 수 가중 점수에 따라 A2 인쇄 밀도(≤1400 short, ≤2800 standard, 그 외 long)를 자동 결정합니다.

7.6 조합 규약 체계 및 다회차 심의 스튜디오 (bylaws.ts, bylaws-law.ts, bylaws-revision.ts)

  • 공개 규약 2종: bylaws-guide.html(12장 59조·부칙 3조·별첨 2건 개괄, 인라인 SVG 거버넌스 체계도, 법정 기한표) 및 bylaws.html(중복 제37조까지 고유 앵커 보존, 실시간 검색·하이라이트·주제 칩 필터·조문 링크 복사).
  • 미등재(unlisted, noindex,follow) 규약 검토 3종 모음:

제10장. 비개발자 관리자를 위한 상황별 실무 운영 매뉴얼 (레시피 A~G)

레시피 A. 신규 조합원 가입 · 탈퇴 · 지부 이동 처리하기

  1. 스캔받은 가입서(또는 탈퇴서) 이미지/PDF 파일을 내 PC에 준비합니다.
  2. npm run union -- member join --name 홍길동 --unit AY --birth 850315 --doc "C:\경로\가입서.jpg"를 실행합니다. (--birth가 과거 탈퇴자와 일치하면 자동으로 재가입으로 이어집니다.)
  3. npm run union -- export-md와 npm run export:public을 순서대로 실행합니다.
  4. Git에는 오직 data/public/만 커밋·푸시합니다. (union.db와 _raw/는 로컬에만 보관)

레시피 B. 임원 선출 · 보직 변경 및 순번제 소통간사 등록하기

  • 공식 임원: role appoint ... --scope executive --disclosure public_official로 임명하면 공개 웹(/union/) 임원 카드와 회의록 허용 목록에 자동 반영됩니다.
  • 순번제 소통간사: --scope staff_rotating을 지정하면 masked로 고정되며 public_official 설정 시 에러로 차단됩니다.
  • 변경 후 반드시 export-md와 export:public을 실행하세요.

레시피 C. 매월 회계 원장 동기화 및 결산서·포털 업데이트하기

  1. Google Sheets 원장을 .xlsx 파일로 다운로드합니다(시트명 통합원장 유지).
  2. 신규 계정(목)이 생겼다면 먼저 config/coa.json에 등록합니다.
  3. npm run union -- sync-ledger --file "C:\다운로드\ledger.xlsx" 실행(3대 검증 및 참조 tx_id 검증 자동 수행).
  4. npm run build:reports로 내부 회의용 실명 결산서(reports/)를 뽑습니다.
  5. npm run export:public → npm run check:local 실행 후 data/public/을 커밋·푸시합니다.

레시피 D. 운영위원회 회의록 작성 및 회계 거래 연결하기

  3. 관련 지출이 있으면 npm run union -- link add --doc mom:YYYYMM --tx HQ-2026-XXX --note "설명" 실행 후 npm run export:public으로 공개 링크 JSON을 갱신합니다.

Chapter 11 · Handover & FAQ

제11장. 인수인계 체크리스트 및 자주 발생하는 문제 해결 (FAQ)

11.1 신임 관리자 인수인계 7대 필수 체크리스트

11.2 자주 만나는 오류 메시지와 해결법 (FAQ 10선)

Q1. Invalid COA at <txId> 오류가 나면서 원장 동기화가 실패합니다.
엑셀 원장에 적힌 (구분, 관, 항, 목) 조합이 config/coa.json 기준표에 없다는 뜻입니다. 오타를 수정하거나 새로운 활동 계정이 필요하면 config/coa.json에 먼저 추가한 뒤 다시 sync-ledger를 실행하세요.
Q2. Balance mismatch at <txId>: expected X, got Y 오류가 납니다.
엑셀 원장의 중간 행을 지우거나 금액을 고친 뒤 단위 잔액(unit_bal) 수식이 맞지 않아 1원 이상 어긋난 상태입니다. 해당 거래번호 앞뒤 행의 수입·지출·잔액 수식을 엑셀에서 바로잡고 다시 시도하세요.
Q3. Formula error '#REF!' 오류가 납니다.
Google Sheets/Excel 셀에 #REF!, #NAME?, #VALUE!, #N/A 같은 시트 수식 오류 문자가 남아 있습니다. 시트에서 해당 오류 셀을 해결한 뒤 다시 내려받으세요.
Q4. document_ledger_links가 참조하는 거래번호가 누락되었습니다 오류가 납니다.
자료실 회의록이나 탈퇴 환급 이력에 이미 연결해 둔 거래번호(tx_id)가 새 원장 파일에서 사라졌거나 번호가 바뀌었습니다. 데이터베이스 참조 무결성을 지키기 위해 자동 롤백되었으니, 엑셀의 기존 tx_id를 복구하세요.
Q5. 소통간사를 public_official로 등록하려니 에러가 납니다.
ADR-0003 원칙상 순번제 소통간사(staff_rotating)는 일반 조합원 보호를 위해 공개 직무자로 설정할 수 없도록 코드에서 차단합니다. --disclosure masked를 쓰거나 플래그를 생략하세요.
Q6. 회의록에 위원장 실명을 적었는데 [finance-zone]: 비공개 인물 성명 노출 오류가 뜹니다.
## 재정 현황, ## 찬조금 같은 재정 제목 아래 구역에서는 선출 임원이라 할지라도 실명 기재를 금지합니다. 해당 구역에서는 "관계자", "임원", "조합원" 등으로 비식별 표기하세요.
Q7. validate:ci에서 해시 비공개 인물 노출 [홍*동] 오류가 발생했습니다.
문서에 비공개 대상자(또는 해당 문서 날짜 기준 임기 외 인물)의 실명이 포함되었습니다. 문서 본문에서 익명 처리하거나, 공식 임원 임기가 누락되었다면 person_roles 수정 후 export:public을 다시 실행하세요.
Q8. PRIVACY_HMAC_SALT 불일치/누락 경고가 뜹니다.
내 PC의 .env 파일 속 솔트 값과 GitHub Repository Settings의 Actions Secret(PRIVACY_HMAC_SALT) 값이 다르면 CI가 해시를 대조하지 못합니다. 두 값을 똑같이 맞춘 후 npm run export:public을 실행해 privacy_hashes.json을 다시 커밋하세요.
Q9. 회의록 검증에서 unbalanced-strong-marker 또는 escaped-bracket-residue가 뜹니다.
Markdown 문법 오류입니다. **굵기** 표기가 닫히지 않았거나 \[ 이스케이프 문자가 화면에 그대로 출력될 위험이 있다는 뜻이니 안내된 줄 번호를 확인해 고쳐 주세요.
Q10. union pdf 실행 시 Chrome 또는 Edge를 못 찾는다고 나옵니다.
브라우저가 비표준 폴더에 설치된 경우입니다. PowerShell에서 $env:CHROME_PATH="C:\실제경로\chrome.exe"를 지정한 뒤 다시 실행하세요.
Chapter 12 · Design & Accessibility

제12장. 가독성·접근성(A11y) 및 디자인 시스템(DESIGN.md) 설계 원칙

union-portal 포털과 지금 보고 계신 이 HTML 인수인계 해설서는 조합원과 관리자가 기기·시력·환경에 상관없이 정보를 얻도록 다음 원칙을 엄격히 지킵니다.

  • Hallmark Ledger 시각 정체성: 카드 박스를 무분별하게 중첩하지 않고, 장부의 굵은 상단 괘선(2px~4px --rule-bar)과 1px 헤어라인, Klein Blue(#002FA7)·Dark Tyrian(#12354E)·로고 코발트(#516DB2) 배색으로 명료한 계층을 만듭니다.
  • 라이트·다크 모드 & 인쇄 분리: <meta name="color-scheme" content="light dark">와 light-dark() 토큰으로 OS 테마를 기본 추종하며 수동 전환 시 FOUC 깜빡임을 막습니다. 반면 종이 인쇄(@media print)와 PDF 출력은 다크 모드의 영향을 받지 않도록 흰 배경·검은 잉크 라이트 전용으로 고정합니다.
  • 타이포그래피와 OS 글자 확대 존중: Pretendard 계열 단일 글꼴과 tabular-nums 숫자 정렬을 쓰며, <meta name="text-scale" content="scale">과 rem/em 상대 단위를 사용해 OS 확대 설정과 본 문서의 글자 크기 조절(85~130%)이 깨짐 없이 동작합니다.
  • WCAG AA 웹 접근성: 본문 바로가기 링크(skip-link), 시맨틱 랜드마크(header, nav, main, aside, footer), :focus-visible 고대비 포커스 링, @container 기반 모바일 카드형 표 전환(data-label), 색맹·고대비 모드(forced-colors: active) 대비용 텍스트·아이콘 병기, 그리고 모든 SVG 다이어그램에 role="img"·<title>·<desc>를 내장했습니다.
