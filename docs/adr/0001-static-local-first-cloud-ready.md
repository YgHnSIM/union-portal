# 비로그인 정적 공개 포털 + 로컬 관리 우선 및 클라우드 이전 경계

조합원 규모(현직 약 60명)와 개인정보 보호 요건을 고려해 1단계는 GitHub Pages 기반 비로그인 정적 공개 포털과 로컬 전용 관리 체계로 운영하되, 향후 다중 지부 편집이나 인증 기능이 필요할 때 클라우드 서버로 이전할 수 있도록 도메인·저장소·표현 계층을 분리한다. 처음부터 서버·클라우드 DB를 운영하면 비용과 개인정보 유출 표면적이 불필요하게 커지므로, 로컬 정적 체계의 안전성을 확보하면서 이전 비용만 구조적으로 낮춘다.

## Considered Options

- **처음부터 클라우드 인증 웹앱 구축**: 지부별 동시 입력은 편하지만, 소규모 노조 운영 단계에서 상시 서버 유지·권한 관리·외부 DB 개인정보 보안 부담이 과도하다.
- **클라우드 이전 고려 없는 완전 정적 스크립트**: 당장은 단순하지만, 파일 경로·JSON 구조가 비즈니스 로직과 결합되어 추후 서버 전환 시 전면 재작성이 필요하다.

## Consequences

- 모든 데이터 읽기·쓰기는 저장소 인터페이스(Repository)를 경유해야 하며, 빌드 스크립트가 로컬 파일 경로에 직접 결합되지 않아야 한다.
- 민감 원본(조합원 명부, 가입서, 원본 원장, 내부 보고서)은 로컬 전용 격리 경계 안에만 보관한다.
